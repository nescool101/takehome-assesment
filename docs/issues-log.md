# Issues we hit and how we resolved them

Kept so reviewers can see what went wrong, not just the final state. Newest last. "Root cause" is what we verified, not a guess.

## Design / plan contradictions (found by checking AI output against the assignment PDF)
| # | Issue | Fix |
|---|---|---|
| 1 | Two AIs assumed an engagement's template version is readable without loading it. The PDF says it is only readable by loading (about 1 minute). | Backfill always costs one load per existing engagement; enumeration only saves finding IDs. |
| 2 | An AI quoted a 67-day backfill for the pessimistic case. 2.4M x 1 min / 50 permits is 33 days (83 at 20 permits). | Recomputed; the doc shows the arithmetic. |
| 3 | The engagement stores the creation version, not the current one. | Hooks on apply/decline are the source of truth going forward. |
| 4 | Retry counted twice: SQS `maxReceiveCount` plus in-process retry would multiply attempts. | First fix (SQS count only) was also wrong, see next row. |
| 5 | SQS `ReceiveCount` also rises on every deferral (firm cap, breaker open), so using it as the retry counter would dead-letter healthy jobs. | Worker keeps its own attempt count (message attribute). `maxReceiveCount` is a safety net at 20. Terraform re-applied. **Not enough on its own:** see 23. |
| 6 | An early draft left the worker with nothing to throttle (steady state made no 1-minute calls). | The 1-minute call is used for backfill and best-effort materialization (plan section 7). |

### Before deploying to real AWS (review round 3)

- Define `ADMIN_TOKEN` (and `CORS_ORIGIN` if a browser UI calls the ops API). Without the token, `/admin/*` returns 403, so the panel and the publish flow fail.
- Run `terraform apply` for `envs/aws`: the `registry` table schema changed (range key `offer`, new GSI `offer-index`).
- Alarms and dashboards on the EMF metrics (namespace `Fanout`, dimension `Service`) are not built yet; that is CloudWatch infrastructure still to do.
- Config is injected, never hardcoded: `Main` has no endpoint, region or credential defaults. Docker Compose sets them for LocalStack; on Kubernetes use a ConfigMap/Secret (or IRSA / pod identity for credentials), on ECS the task definition and task role, and Terraform can render either (`REGION_NAME`, `ADMIN_TOKEN`, `CORS_ORIGIN`, `AWS_REGION`).
- Circuit breaker is now shared by every worker of a region: consecutive-failure count and reopen time live in one item of the idempotency table (atomic `ADD`/conditional updates, read cache 500 ms), and the half-open probe is a ShedLock (`shedlock-provider-dynamodb2`) lock held for the cooldown, so only one worker probes. Needs the new `<region>-locks` table (`terraform apply`). If the store is unreachable a worker falls back to its own failure count. Still per process: the per-firm limiter (a shared one needs a counter per firm; add when firm-level starvation shows up in the EMF metrics).
